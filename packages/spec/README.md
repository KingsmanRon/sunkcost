# packages/spec — Sunkcost v1 contracts

The contracts every other component implements (C1 in `docs/ARCHITECTURE.md`). Nothing here runs in
production except the Pydantic models, which the API and worker import.

| Path | What it is |
|---|---|
| `schemas/*.v1.json` | JSON Schema 2020-12 for each wire document. `common.v1.json` holds shared `$defs`. |
| `sunkcost_spec/` | Pydantic v2 models mirroring the schemas (internal package, never published) |
| `features/features.v1.md` | Normative definition of the 12 decision features and the logistic score |
| `vectors/` | Golden test vectors, generated by `tools/gen_vectors.py` (see below) |
| `fixtures/` | Example documents: `valid/`, `invalid/` (both validators reject), `invalid-semantic/` (only the models reject) |
| `prices/prices.v1.json` | USD list prices per 1M tokens, each entry with `source_url` and `retrieved_at` |

## Rules

- Every document type carries `"schema_version": "1"` and every schema file has an `$id`.
- No JSON floats anywhere. Money is a decimal string with at most 9 fractional digits
  (`numeric(20,9)` in Postgres). Scores, thresholds and model parameters are float64 values written
  as decimal strings (Python `repr(float)`, the shortest round-trip form); both SDKs parse them to
  IEEE-754 float64.
- Timestamps are UTC RFC 3339 with a literal `Z`. Parsers keep microseconds and truncate further digits.
- IDs are lower-case UUIDs; `run_id` must be a UUIDv7.
- Every ingest event field is required; optional values are sent as `null`. In `outcome.v1`, optional
  fields are omitted instead (the run is addressed by `run_id` or by `(workload, external_ref)`).
- Regular expressions use the subset shared by ECMA-262, Python `re` and Rust `regex`; `$` means end
  of input. `sunkcost_spec/patterns.py` repeats every pattern and a test keeps the two identical.

### Conformance

`tests/test_conformance.py` enforces, for every schema:

1. The schema is valid JSON Schema 2020-12, and every `$ref` resolves.
2. Every file in `fixtures/valid/` validates against its schema (ECMA-262 regex semantics) and
   parses with the matching Pydantic model, and `model_dump(mode="json", exclude_unset=True)`
   returns the original document unchanged.
3. Every file in `fixtures/invalid/` is rejected by both the schema and the model.
4. Every file in `fixtures/invalid-semantic/` passes the schema but is rejected by the model. These are
   rules JSON Schema cannot express: cross-field comparisons, finiteness, integral floats such as `1.0`.

Fixture names are `<schema>--<case>.json`, e.g. `bundle.v1--minimal.json`. The TypeScript SDK runs the
same fixtures through its own types in P6.

### Vectors

`python tools/gen_vectors.py` regenerates every file in `vectors/`; `--check` fails if the committed
files differ. The generator is a direct, non-incremental implementation of `features.v1.md`, written
separately from `sunkcost.core`, so the core is tested against an independent reference.

| Directory | Contents | Tolerance |
|---|---|---|
| `features.v1/` | Step sequences with the expected feature vector and logistic score after every prefix `k = 0..n` | relative 1e-12 |
| `canonical-json/` | Object, canonical bytes (hex) and Ed25519 signature; also inputs that must be rejected | exact |
| `holdout.v1/` | `run_id` to holdout bucket, and holdout flags at several rates | exact |
| `args-hash.v1/` | Salt and tool arguments to canonical bytes and `hmac-sha256:` hash | exact |

Signatures in the vectors use the RFC 8032 section 7.1 TEST 1 key, which is public. It is a test key:
no SDK trusts `key_id` `rfc8032-test-1` by default.

### Price lookup

Used only when `record_step()` is called without `cost_usd`:

1. Find the entry whose `model` or one of its `aliases` equals the step's `model` exactly.
   No match, or no model: `cost_usd` is `null` (unknown; features and savings count it as 0).
2. Take the price with the latest `effective_from` on or before the step's UTC date; if the step
   predates every entry, take the earliest.
3. If a tier has `above_input_tokens` < the step's `input_tokens`, the tier with the largest such
   `above_input_tokens` replaces `input` and `output` for that step.
4. `cost = (input_tokens * input + output_tokens * output) / 1,000,000` in exact decimal arithmetic,
   rounded half-even to 9 fractional digits.

List prices ignore prompt-caching discounts, batch pricing and provider-specific surcharges. Pass
`cost_usd` when you know the billed amount.
